## 项目结构

- 后端：基于Spring Boot（Java），使用Maven构建，模块化分层清晰（controller、service、mapper、entity、config、common等）。
- 前端：基于Vue 3 + Vite，模块化组织（api、views、components、store、utils、router等），并提供E2E测试用例。

## 架构总览
系统采用典型的前后端分离架构：前端通过HTTP API与后端交互，后端以RESTful风格暴露接口，数据持久化由关系型数据库完成。鉴权通过JWT在拦截器中校验，审计日志通过拦截器记录操作轨迹。

```mermaid
participant SVC as "服务层"
participant DB as "数据库"
U->>FE : 打开登录页面
FE->>API : POST /auth/login
API->>SVC : 验证用户名密码
SVC->>DB : 查询用户信息
DB-->>SVC : 返回用户数据
SVC-->>API : 返回用户上下文
API-->>FE : 返回令牌与用户信息
FE->>FE : 保存令牌到本地存储

FE->>API : 携带令牌发起请求
API->>API : 拦截器校验令牌
API-->>FE : 返回业务数据
```

## 详细组件分析

### 认证与授权流程
- 登录流程
  - 前端提交账号密码至后端登录接口。
  - 后端校验凭证并生成JWT令牌返回前端。
  - 前端将令牌存入本地存储并在后续请求头中携带。
- 鉴权流程
  - 后端拦截器解析请求头中的令牌，校验有效性并注入用户上下文。
  - 未通过校验的请求直接返回错误响应。

```mermaid
flowchart TD
Start(["开始"]) --> LoginReq["前端发送登录请求"]
LoginReq --> Validate["后端校验凭证"]
Validate --> Valid{"校验通过?"}
Valid --> |否| ErrorResp["返回错误响应"]
Valid --> |是| GenToken["生成JWT令牌"]
GenToken --> ReturnToken["返回令牌给前端"]
ReturnToken --> SaveToken["前端保存令牌"]
SaveToken --> NextReq["后续请求携带令牌"]
NextReq --> Intercept["拦截器解析并校验令牌"]
Intercept --> TokenValid{"令牌有效?"}
TokenValid --> |否| AuthError["返回未授权错误"]
TokenValid --> |是| Proceed["继续执行业务逻辑"]
Proceed --> End(["结束"])
AuthError --> End
ErrorResp --> End
```

### 常见问题与解决方案
- 跨域问题
  - 检查后端CORS配置与前端请求域名；必要时启用代理。
- 令牌失效
  - 刷新令牌策略；前端自动重试与错误提示。
- 数据库连接失败
  - 核对连接参数与权限；检查防火墙与网络连通性。
