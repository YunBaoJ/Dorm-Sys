# 管理员端管理能力完善设计

## 目标

补齐管理员端的公告管理、操作日志和数据报表，使管理员角色具备全局信息发布、关键操作追溯和宿舍运行数据汇总能力。功能以毕业答辩演示为边界，不引入复杂工作流、消息队列或第三方报表平台。

## 功能范围

### 公告管理

- 复用现有 `business_record` 表，使用独立业务类型 `admin_notice`。
- 管理员可以新增、编辑、删除公告，并在“草稿”和“已发布”之间切换。
- 公告字段包括标题、正文、状态、发布时间和创建人。
- 学生端公告列表读取已发布的管理员公告；宿管原有消息记录保持不变。
- 管理员不能通过请求修改公告创建人等归属字段。

### 操作日志

- 新建 `operation_log` 表，与业务记录分离。
- 记录管理员执行的 POST、PUT、DELETE 请求，包括操作人、模块、动作、请求路径、结果、时间和必要摘要。
- 不记录密码、令牌、完整请求体或其他敏感字段。
- 登录、查询和操作日志自身的读取不重复写日志。
- 操作日志页面只读，支持模块、结果和关键词筛选。

### 数据报表

- 数据直接聚合现有楼栋、房间、床位和报修表，不保存重复统计快照。
- 展示全局楼栋数、房间数、床位数、入住数、入住率、空床位数、报修总数、已完成数和完成率。
- 提供按楼栋对比的房间数、床位数、入住数和入住率。
- 支持将当前报表导出为 UTF-8 BOM CSV，确保 Windows Excel 可直接打开中文。
- 报表只对管理员开放。

## 架构与数据流

### 后端

- `OperationLog` 使用独立 Entity、Mapper、Service 和 Controller。
- 审计记录通过 Spring MVC 拦截器在请求结束后写入；只拦截管理员的变更请求。
- `AdminReportController` 负责实时聚合统计，避免前端重复计算业务口径。
- 公告继续通过 `BusinessRecordController`，增加管理员公告的数据范围和字段保护。
- 应用启动时以 `CREATE TABLE IF NOT EXISTS` 初始化 `operation_log`，兼容当前无迁移工具的项目结构。

### 前端

- 管理员侧栏新增“公告管理”“操作日志”“数据报表”。
- 三个页面分别负责公告 CRUD、日志筛选和报表展示/导出。
- API 模块按领域拆分，避免将日志、公告和报表请求混入同一文件。

## 权限与安全

- 三个模块均要求 `admin` 角色。
- 宿管和学生访问管理员接口返回 403。
- 操作日志摘要采用白名单字段，不保存密码、Authorization 请求头或登录凭据。
- 导出由前端使用已加载的报表数据生成，不暴露额外下载接口。

## 错误处理

- 公告缺少标题或正文时返回 400。
- 非管理员修改管理员公告时返回 403。
- 报表无数据时返回零值和空楼栋列表，不返回服务端错误。
- 日志写入失败不得阻断原业务请求，只记录服务端错误日志。

## 测试与验收

- 后端测试覆盖公告权限、管理员公告 CRUD、审计日志字段脱敏、报表统计口径和空数据。
- E2E 覆盖管理员三个菜单可访问、公告表单可操作、日志列表可筛选、报表 CSV 可触发导出。
- 全量 Maven 测试、前端生产构建和 Playwright E2E 必须通过。
- 学生、宿管现有登录和核心页面不得回归。

## 不包含

- 审批流、定时发布、公告附件、日志删除、PDF 报表、定时报表邮件和历史统计快照。
