## 一、性能优化

### 1.1 N+1 查询问题修复（核心优化）

**问题描述**：所有 Controller 中直接使用 `service.list()` 全表查询，然后在内存中过滤，导致每次请求都加载整个表的数据。涉及 Room、FeeBill、RepairRequest、HygieneRecord、TransferRequest、VisitorRecord、Bed 等 7 个核心模块。

**优化措施**：

| 文件 | 优化内容 |
|------|----------|
| `RoomService` / `RoomController` | 新增 `listRoomsWithDetails()` 按需查询，使用 `bedService.count()` 统计占用数替代全表加载 |
| `FeeBillService` / `FeeBillController` | 新增 `listFeeBillsWithDetails()` 按需加载，使用 `roomService.getById()` + `buildingService.getById()` 替代全表 |
| `RepairRequestService` / `RepairRequestController` | 新增 `listRepairRequestsWithDetails()` 使用 `userService.listByIds()` 只加载相关用户 |
| `HygieneRecordService` / `HygieneRecordController` | 同上模式，按需查询关联数据 |
| `TransferRequestService` / `TransferRequestController` | `listTransferRequestsWithDetails()` 按需加载关联数据 |
| `VisitorRecordService` / `VisitorRecordController` | `listVisitorRecordsWithDetails()` 按需加载用户信息 |
| `BedService` / `BedController` | `listBedsWithDetails()` 按需加载学生信息 |

**效果**：将 O(N) 次数据库查询降为 O(1)，避免全表扫描。

### 1.2 Dashboard 统计查询优化

**优化内容**：
- `/getBuildingStats` 端点逻辑下沉到 `BuildingServiceImpl.getBuildingsWithStats()`，复用已有方法
- 使用 `roomService.list(wrapper)` + `bedService.list(wrapper)` 按需加载计算床位统计
- 顶部统计数据改用 `count()` 聚合查询替代 `list().size()` 内存计数

### 1.3 AdminReportController 全表查询优化

**优化内容**：
- 顶部统计汇总使用 MyBatis-Plus `count()` 替代全表 `list()` + 内存过滤
- 楼栋明细使用 `in("building_id", buildingIds)` 按需加载房间/床位数据
- 删除 `belongsToBuilding()` 等冗余方法

### 1.4 分页支持

**覆盖范围**：所有 Controller 的 list 接口

**变更内容**：
- 统一添加 `@RequestParam(defaultValue = "1") Integer page` 和 `@RequestParam(defaultValue = "100") Integer size` 参数
- 使用 MyBatis-Plus `Page<T>` 对象包装分页查询结果
- 前端保留原有展示逻辑，后端按需返回分页数据

**涉及 Controller**：
- `FeeBillController.list()`
- `RepairRequestController.list()`
- `HygieneRecordController.list()`
- `TransferRequestController.list()`
- `VisitorRecordController.list()`
- `BedController.list()`
- `RoomController.list()`
- `UserController.list()`
- `ItemRecordController.list()`
- `LateReturnRecordController.list()`
- `CallRecordController.list()`
- `OperationLogController.list()`
- `BusinessRecordController.list()`

### 1.5 数据库索引补充

在 `schema.sql` 中添加以下索引以加速常用查询路径：

```sql
CREATE INDEX idx_visitor_student_id ON visitor_record(student_id);
CREATE INDEX idx_hygiene_room_id ON hygiene_record(room_id);
CREATE INDEX idx_hygiene_check_date ON hygiene_record(check_date);
CREATE INDEX idx_feedback_student_id ON feedback(student_id);
CREATE INDEX idx_transfer_student_id ON transfer_request(student_id);
CREATE INDEX idx_call_student_id ON call_record(student_id);
CREATE INDEX idx_late_return_student_id ON late_return_record(student_id);
```

### 1.6 DormManagerScopeService 缓存优化

**优化内容**：为 `managedBuildingIds()`、`managedRoomIds()`、`managedStudentIds()` 方法添加内存缓存层

**实现方式**：
- 使用 `ConcurrentHashMap` 存储缓存条目
- TTL（存活时间）设为 5 秒，避免频繁查库
- 内部 `CacheEntry` 类记录时间戳，自动过期失效

## 三、代码重构与架构改进

### 3.1 Service 层重构（业务逻辑下沉）

**核心原则**：将 Controller 中的所有业务逻辑下沉到 Service 层

**重构模式**：
- Service 接口新增 `listXxxWithDetails()` 方法
- ServiceImpl 中实现按需查询逻辑
- Controller 中删除全表查询逻辑，改为调用 Service 方法

**重构涉及模块**：

| 模块 | Service 接口 | Service 实现 | Controller |
|------|-------------|-------------|------------|
| 房间管理 | `RoomService` | `RoomServiceImpl` | `RoomController` |
| 费用账单 | `FeeBillService` | `FeeBillServiceImpl` | `FeeBillController` |
| 报修管理 | `RepairRequestService` | `RepairRequestServiceImpl` | `RepairRequestController` |
| 卫生管理 | `HygieneRecordService` | `HygieneRecordServiceImpl` | `HygieneRecordController` |
| 调宿管理 | `TransferRequestService` | `TransferRequestServiceImpl` | `TransferRequestController` |
| 访客管理 | `VisitorRecordService` | `VisitorRecordServiceImpl` | `VisitorRecordController` |
| 床位管理 | `BedService` | `BedServiceImpl` | `BedController` |

### 3.2 Controller 构造器注入

**变更内容**：所有 Controller 将 `@Autowired` 字段注入改为构造器注入

**优势**：
- 依赖关系显式化，便于单元测试
- 避免循环依赖（配合 `@Lazy`）
- 符合 Spring 官方推荐的最佳实践
- 提升代码可测试性和可维护性

**涉及文件**（共 16 个）：
- `AuthController`、`UserController`、`RoomController`
- `BedController`、`FeeBillController`、`RepairRequestController`
- `HygieneRecordController`、`TransferRequestController`
- `VisitorRecordController`、`ItemRecordController`
- `LateReturnRecordController`、`CallRecordController`
- `OperationLogController`、`DashboardController`
- `AdminReportController`、`BusinessRecordController`

### 3.3 循环依赖修复

**修复的循环引用链**：
```
BuildingServiceImpl → RoomService → RoomServiceImpl → BuildingService
RoomServiceImpl → BedService → BedServiceImpl → RoomService
BedServiceImpl → DormManagerScopeService → DormManagerScopeServiceImpl → BedService
```

**解决方案**：在字段注入点添加 `@Lazy` 注解，让 Spring 注入代理对象而非立即解析，打破循环链。

**涉及文件**：
- `BuildingServiceImpl`（RoomService、BedService 加 `@Lazy`）
- `DormManagerScopeService`（RoomService、BedService 加 `@Lazy`）

## 五、系统稳定性提升

### 5.1 全局异常处理增强

**变更文件**：`GlobalExceptionHandler.java`

**新增异常处理器**：

| 异常类型 | HTTP 状态码 | 场景 |
|----------|------------|------|
| `MethodArgumentNotValidException` | 400 Bad Request | 请求参数校验失败 |
| `HttpMessageNotReadableException` | 400 Bad Request | 请求体格式错误 |
| `MissingServletRequestParameterException` | 400 Bad Request | 缺少必填参数 |
| `DataIntegrityViolationException` | 409 Conflict | 数据库约束冲突 |
| `HttpRequestRequestMethodNotSupportedException` | 405 Method Not Allowed | 请求方法不支持 |

### 5.2 日志系统配置

**新建文件**：`logback-spring.xml`

**配置内容**：

| 配置项 | 说明 |
|--------|------|
| 控制台输出 | 开发环境可见，生产环境关闭 |
| 滚动文件日志 | 按天滚动，保留 30 天 |
| SQL 日志独立文件 | `logs/sql/` 目录，开发环境记录 Mapper 级别 DEBUG 日志 |
| 多 Profile 支持 | dev 环境输出控制台 + 文件，prod 环境仅文件 |
| 日志格式 | 包含时间戳、线程名、日志级别、类名、消息 |

### 5.3 开发环境 SQL 日志

**新建文件**：`application-dev.yml`

**配置内容**：
```yaml
mybatis-plus:
  configuration:
    log-impl: org.apache.ibatis.logging.slf4j.Slf4jImpl
```

配合 `logback-spring.xml` 中的 dev profile 配置，在开发环境下自动输出 SQL 执行日志到独立文件，方便调试。
