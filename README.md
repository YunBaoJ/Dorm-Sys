# 学生宿舍管理系统

基于 **Spring Boot + Vue 3** 前后端分离架构的学生宿舍管理系统，面向学生、宿管员、管理员三类角色，覆盖宿舍资源管理、业务申请流转、日常服务与沟通等完整业务闭环。

---

## 系统架构

### 总体架构

```
浏览器 → Vue 3 前端 → /api + Bearer JWT → Vite 代理 → Spring Boot REST API
                                                          ↓
                                             JWT 认证与权限拦截器
                                                          ↓
                                             MyBatis-Plus 服务与 Mapper
                                                          ↓
                                                   MySQL 数据库
                                                          ↓
                                             管理员操作审计日志
```

### 分层设计

| 层级 | 实现 | 职责 |
|------|------|------|
| 展示层 | Vue SFC、Element Plus、Lucide 图标 | 三端页面、表单、表格、看板和交互反馈 |
| 状态与路由层 | Pinia、Vue Router | 登录态、用户信息、角色路由和页面访问隔离 |
| 通信层 | Axios | 统一 REST 请求，自动携带 JWT，统一处理认证失效 |
| 接口层 | Spring MVC Controller | 参数校验、角色与数据范围控制 |
| 业务层 | Spring Service + 事务 | 床位分配、调宿同步、批量建房、统计聚合 |
| 数据访问层 | MyBatis-Plus Mapper | 实体与 MySQL 表映射、条件查询 |
| 横切层 | JWT 拦截器 + 审计拦截器 | 身份认证、角色授权、管理员变更审计 |

## 角色与权限模型

### 三类角色

| 角色 | 数据范围 | 核心权限 |
|------|---------|---------|
| 学生（student） | 仅本人数据 | 查看宿舍信息、提交申请、室友聊天、费用查询 |
| 宿管员（dormmanager） | 所负责楼栋 | 入住管理、报修处理、访客审批、卫生检查、调宿审批、晚归登记、水电计费 |
| 管理员（admin） | 全局 | 用户管理、资源管理、公告管理、操作日志审计、数据报表 |

### 认证与授权流程

1. 用户登录提交账号密码，后端校验角色和 BCrypt 密码哈希后签发 JWT
2. 前端后续请求在 Authorization 头携带 Bearer Token
3. JwtAuthInterceptor 解析令牌并注入请求上下文
4. 拦截器拒绝无令牌、过期令牌和越权请求
5. 宿管数据范围根据 manager_info.building_id 限制到负责楼栋
6. 管理员变更操作自动记录操作日志

### 权限控制要点

- 学生不可创建或修改楼栋、房间、床位、全局费用等资源
- 学生不可读取用户列表、全楼栋分布和管理员统计数据
- 宿管仅能操作其负责楼栋内的学生、房间和业务记录
- 管理员报表和操作日志仅管理员可访问
- 聊天限制为同寝室范围：私聊双方必须同寝，群聊仅限本寝室

## 关键业务流程

### 入住与床位分配

新建房间时根据 capacity 自动生成对应数量的空闲床位。宿管或管理员分配床位后更新 bed.student_id 和 status，并同步更新 room.status。床位状态含 EMPTY、OCCUPIED、BROKEN；房间状态含 NORMAL、FULL、MAINTENANCE。

### 调宿审批与事务同步

1. 学生提交调宿申请，状态设为 PENDING
2. 宿管审批时，APPROVED 后在事务中校验目标房间有空床
3. 释放原床位 → 分配目标床位 → 清理可能存在的其他重复床位
4. 重新计算原房间和目标房间状态，确保数据一致

### 批量创建房间

管理员选择楼栋、楼层范围、每层房间数和容量，后端校验后使用事务批量插入房间并自动为每个房间生成对应数量的空闲床位，任一步失败则回滚。

### 室友聊天

- 私聊：双方必须同寝室
- 群聊：绑定当前用户所在房间，禁止跨房间
- 私聊和群聊各最多查询最近 200 条，通知最多 30 条

### 公告管理

公告存储于通用业务记录表，类型为 admin_notice。草稿不对学生可见，学生端仅返回已发布记录的必要展示字段。

## 本地运行

### 前置条件

- JDK 17
- Node.js 18+
- MySQL 服务已启动

### 1. 克隆项目

```bash
git clone https://github.com/YunBaoJ/Dorm-Sys.git
cd Dorm-Sys/Dorm-Sys
```

### 2. 数据库初始化

在 MySQL 中执行 backend/src/main/resources/schema.sql 创建表结构，可按需执行种子数据脚本。

### 3. 启动后端

```bash
cd backend
.\mvnw.cmd spring-boot:run
```

后端地址：http://127.0.0.1:8088

### 4. 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端地址：http://127.0.0.1:5173

## 部署

### 前端（Vercel）

1. 在 Vercel 导入本仓库
2. 设置 Root Directory 为 Dorm-Sys/frontend
3. 添加环境变量 VITE_API_BASE_URL → 后端部署地址
4. 部署

### 后端（Railway / Render / VPS）

需要 Java 17 + MySQL 环境，通过环境变量配置：

| 变量 | 说明 |
|------|------|
| DB_URL | MySQL 连接地址 |
| DB_USERNAME | 数据库用户名 |
| DB_PASSWORD | 数据库密码 |
| JWT_SECRET | JWT 签名密钥 |

## 技术亮点

- **角色与数据范围双层隔离**：三角色路由 + 宿管楼栋范围控制，实现权限和数据隔离
- **床位为中心的住宿模型**：以床位为事实来源，调宿事务同步更新床位、房间和学生展示
- **批量资源初始化**：支持一键批量创建房间并自动生成对应数量的床位
- **同寝室聊天隔离**：消息仅限同寝室成员可见，减少信息暴露
- **公告状态分离**：草稿/发布隔离，学生端仅获取已发布的必要字段
- **操作审计追溯**：管理员变更自动记录操作日志，支持按模块和时间追溯
- **实时数据报表**：楼栋、房间、床位、报修数据实时聚合，支持 CSV 导出
